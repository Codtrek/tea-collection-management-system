\section{Project Constraints and Assumptions}
\label{sec:constraints_assumptions}

\subsection{Constraints}
\begin{itemize}
	\item \textbf{Internet connectivity limitations:} The system may experience reduced functionality in rural plantation areas with poor internet connectivity. Some features may require stable mobile data access for synchronization.
	\item \textbf{Registration required for access:} Only registered and authenticated users can create requests or manage tea collection operations. Unregistered users cannot access platform functionalities.
	\item \textbf{Pending requests only:} Tea Collection Agents are only allowed to act on delivery requests that are currently marked as pending. Completed or finalized deliveries cannot be modified.
	\item \textbf{Agent-entered actual weight:} The final measured weight of collected tea leaves can only be recorded by the assigned Tea Collection Agent, to maintain consistency in records.
	\item \textbf{Photographic verification required:} Collection and delivery confirmations must be accompanied by photographic evidence, since SMS/OTP-based verification is unreliable in areas with poor network coverage.
	\item \textbf{Completed deliveries locked:} Once a delivery is confirmed with photographic evidence, Tea Estate Managers and Owners cannot edit or delete the associated record.
	\item \textbf{Mandatory estate and route information:} Tea Estate Owners are required to provide valid estate location details for route mapping and agent assignment.
	\item \textbf{Single agent assignment:} Each delivery request can only be accepted and managed by a single Tea Collection Agent at a time.
	\item \textbf{Limited offline functionality:} Real-time synchronization and notifications may be delayed or unavailable without internet connectivity, though core data entry (collection details, photos) is supported offline via local storage and synced once connectivity is restored.
	\item \textbf{Android-first support:} The first version of the mobile application will primarily support Android devices. iOS support may be added in future versions.
	\item \textbf{Fixed request workflow:} Delivery requests must follow the sequence: Submitted $\rightarrow$ Approved $\rightarrow$ Agent Assigned $\rightarrow$ Collected $\rightarrow$ Confirmed. Requests cannot skip stages or move backward once updated.
	\item \textbf{Role-based access:} Each user role (Tea Estate Owner, Manager, Collection Agent, Receiving Officer, Factory Administrator, Officer, Manager) can only access functions and data relevant to their assigned role.
	\item \textbf{Valid weight and quantity ranges:} The system restricts invalid values such as negative or zero weights during tea collection and fertilizer request entries.
	\item \textbf{Permanent historical records:} Completed transaction, delivery, and payment records are stored permanently for transparency and audit purposes.
	\item \textbf{Network-dependent notifications:} Push notifications and real-time updates may be delayed if users have unstable internet connections.
	\item \textbf{Unique identifier per account:} Each registered account must use a unique mobile number or employee ID to prevent duplicate accounts.
	\item \textbf{Photo storage dependency:} Photographic evidence upload and verification depend on connectivity to Cloudinary; photos captured offline are queued locally until upload succeeds.
	\item \textbf{Language barrier:} Field users such as Tea Collection Agents and Tea Estate Managers may have limited English proficiency, requiring the interface to support local languages (Sinhala/Tamil) for effective adoption.
\end{itemize}

\subsection{Assumptions}
\begin{itemize}
	\item \textbf{Smartphone ownership:} The system assumes that Tea Collection Agents, Tea Estate Managers, and other field-facing users have access to Android smartphones with a functioning camera capable of running the mobile application.
	\item \textbf{Basic mobile literacy:} It is assumed that estate owners, managers, and agents can perform basic mobile operations such as login, form submission, photo capture, and viewing records.
	\item \textbf{Accurate agent measurements:} The system assumes Tea Collection Agents use properly calibrated measuring equipment and record accurate tea leaf weights during collection.
	\item \textbf{Mostly available network:} The system assumes users have at least occasional access to mobile internet for synchronization and notification delivery.
	\item \textbf{Accurate user details:} The system assumes that all users enter valid names, contact details, and estate/factory location information during registration.
	\item \textbf{Trust in digital records:} The system assumes that estate owners, managers, and factory staff will use the shared digital records and photographic evidence as the primary source of transaction and delivery history.
	\item \textbf{Photographic evidence sufficiency:} The system assumes photographic evidence, combined with agent and manager confirmation, provides adequate verification of tea leaf collection without requiring OTP-based confirmation.
	\item \textbf{Industry-standard workflows:} The system assumes that current tea collection workflows (plucking, verification, delivery, payment) remain generally consistent across the estates and factories involved.
	\item \textbf{Future sector expansion:} It is assumed that other agricultural collection sectors (e.g., rubber, cinnamon) follow workflows broadly similar to tea collection and could be integrated into the system in future versions.
	\item \textbf{Small-scale initial rollout:} The first version assumes a limited number of estates, factories, and users during the initial deployment and testing phase.
	\item \textbf{Devices available in the field:} The system assumes Tea Collection Agents and managers will have access to their mobile devices and adequate camera quality while performing collection and verification activities.
	\item \textbf{Timely agent response:} The system assumes Tea Collection Agents respond to assigned delivery requests within operational timeframes.
	\item \textbf{Requests created after plucking:} The application assumes tea leaf selling requests are created only after plucking is completed and reported by the Tea Estate Manager.
	\item \textbf{Functional measuring tools:} The system assumes Tea Collection Agents use properly calibrated measuring tools during weight verification.
	\item \textbf{Preference for digital records:} It is assumed users are willing to transition from paper-based record keeping to digital systems over time.
\end{itemize}
